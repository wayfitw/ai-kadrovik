# AI-Кадровик — инструкции для Claude Code

Система кадрового делопроизводства РФ с ИИ-агентом. Сейчас строится **MVP (этап 1)**:
ручной ввод данных кадровиком, формирование документов, расчёт сроков, журнал.
Без агента, без порталов, без реальной отправки в госорганы.

Срок MVP: 7–27 октября 2026 (3 недели). План по неделям — `docs/03-BACKLOG-MVP.md`.

## Стек

Python 3.12 · FastAPI · SQLAlchemy 2 + Alembic · PostgreSQL 16 · Redis ·
Celery (воркеры и расписание) · Jinja2 + docxtpl → DOCX → PDF (LibreOffice headless) ·
Next.js 14 + TypeScript (кабинет) · Docker Compose.

Temporal откладываем: в MVP достаточно явной машины состояний в коде + Celery.

## Неизменяемые принципы

1. **Правовая логика живёт в реестре правил, а не в коде.** Сроки, пределы, вид дней,
   формулы — параметры правила в БД, загруженные из `docs/legal-package/01-RULES-REGISTRY.md`.
   Код читает параметры, а не хардкодит `14` или `0.13`.
2. **Каждый параметр правила должен исполняться.** Если правило объявляет категории
   исключений — код обязан их проверять. Линтер `scripts/lint_registry.py` падает,
   если у параметра нет точки исполнения. Это закрывает главный риск проекта.
3. **Уровень автономии проверяется до действия.** Действия A2 получают только
   «подготовить» и попадают в очередь решений. Действий A3 в коде не существует —
   ни функции, ни эндпоинта, ни флага.
4. **Правовую логику не «улучшать» самостоятельно.** Расхождения из
   `docs/04-DOMAIN-NOTES.md` намеренно не исправлены до вердикта юриста. Если видишь
   сомнительный срок или формулу — реализуй как в реестре и добавь запись
   в `docs/04-DOMAIN-NOTES.md`, раздел «Найдено при разработке».
5. **Аудит append-only.** Таблица `audit_log` без UPDATE/DELETE на уровне прав БД,
   каждая запись хранит хеш предыдущей.
6. **Версии фиксируются.** Процесс хранит `rule_version_id` и `template_version_id`,
   по которым стартовал. Изменение правила = новая версия, старые процессы не трогаются.
7. **Текст документов — только из шаблонов.** LLM в MVP не используется вообще.
8. **ПДн.** Паспортные данные, СНИЛС, ИНН — в отдельных зашифрованных колонках
   (ключ на организацию). В логи и аудит ПДн не пишутся, только идентификаторы.

## Структура репозитория (целевая)

```
backend/
  app/
    core/          # settings, db, security, audit
    registry/      # модели правил, версий, загрузчик из markdown, линтер
    employees/     # работники, кандидаты, документы-удостоверения, валидаторы
    processes/     # машины состояний: hiring, probation, vacation, dismissal
    documents/     # шаблоны, рендер DOCX/PDF, версии
    obligations/   # обязательства перед госорганами, календарь сроков, заглушка ЭДО
    decisions/     # очередь решений руководителя (A2)
    calendar/      # производственный календарь, рабочие/календарные дни
    api/           # роутеры FastAPI
  alembic/
  tests/
  scripts/lint_registry.py
frontend/          # Next.js кабинет
templates/         # 22 DOCX-шаблона (docxtpl)
docs/
docker-compose.yml
```

## Правила работы

- Работай по бэклогу блоками: один блок — одна ветка — один PR с тестами.
- Любой расчёт дат — через `app/calendar`, с тестами на граничные случаи
  (31 марта + 1 месяц, 29 февраля, переносы праздников).
- Числовые параметры из реестра покрываются тестами «правило → ожидаемое поведение»
  на контрольных примерах из `docs/04-DOMAIN-NOTES.md`.
- В конце дня формируй сводку для дневного акта: задачи, часы, артефакты
  (ветка, миграция, адрес стенда). Формат — `docs/DAILY-ACT-TEMPLATE.md`.
- Не добавлять функции из «вне MVP» (`docs/02-MVP-SCOPE.md`), даже если просто.
- Комментарии и имена сущностей в коде — на английском, тексты документов
  и интерфейса — на русском.
