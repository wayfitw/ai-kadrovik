# 02. Пошаговые схемы реализованных процессов

> Описывается фактическое поведение программы на дату 28.08.2026.
> Все правовые основания — проектные, каждое требует проверки.

## Условные обозначения

| Знак | Значение |
|---|---|
| 🤖 | Шаг выполняется программой без участия человека |
| ⏳ | Программа выполняет сама, но заранее уведомляет и даёт время отменить |
| 👤 | Шаг не выполняется, пока уполномоченное лицо не примет решение |
| ⛔ | Программа останавливает процесс и передаёт его человеку |
| ⚠ | Место, требующее особого внимания юриста |

**Уполномоченное лицо** — в программе это руководитель организации.
Только он подписывает документы электронной подписью работодателя
и подтверждает юридически значимые решения.

---

## 1. Приём на работу

### Схема

```
👤 Руководитель: «принять Иванова менеджером с 1 сентября, оклад 120 000»
   │
🤖 1. Создание заявки
   │  • сверка со штатным расписанием: есть ли должность, есть ли свободная ставка,
   │    совпадает ли оклад. Расхождение → предупреждение, но НЕ блокировка ⚠
   │  • формирование перечня документов исходя из требований должности
   │
🤖 2. Приглашение кандидата
   │  • персональная ссылка на защищённую страницу, срок действия 14 дней
   │  • напоминания при недоборе документов, не более 3 раз
   │
👤 3. Кандидат вводит данные документов
   │
🤖 4. Проверка полученных данных
   │  • контрольное число СНИЛС и контрольные разряды ИНН
   │  • срок действия паспорта с учётом замены в 20 и 45 лет
   │  • сверка Ф. И. О. между документами → расхождение выносится человеку
   │
🤖 5. Проверки перед оформлением
   │  • возраст: моложе 18 → медосмотр обязателен, испытание исключается,
   │    сокращённое рабочее время; моложе 16 → согласие родителя и органа опеки
   │  • моложе 14 → ⛔ приём остановлен
   │  • иностранный гражданин → проверка срока разрешительного документа;
   │    истёк → ⛔ приём остановлен
   │  • подлежит воинскому учёту → планируется постановка на учёт
   │  • бывший госслужащий → планируется уведомление прежнего нанимателя
   │  • медосмотр требуется по должности, книжка не загружена → ⛔ приём остановлен
   │  • реестр дисквалифицированных лиц — ⚠ ПРОВЕРКА НЕ АВТОМАТИЗИРОВАНА,
   │    выполняется человеком
   │
👤 6. Согласия работника (до электронного подписания)
   │  • на обработку персональных данных
   │  • на электронный документооборот — отказ допустим, тогда бумажный порядок
   │  • на электронный способ ведения сведений о трудовой деятельности
   │
🤖 7. Формирование пакета документов
   │  трудовой договор · приказ о приёме (Т-1) · согласие на обработку
   │  персональных данных · согласие на электронный документооборот ·
   │  заявление о способе ведения трудовой книжки · личная карточка (Т-2) ·
   │  лист ознакомления с локальными актами
   │  + договор о полной материальной ответственности, если должность входит
   │    в перечень
   │
👤 8. Проверка и подписание работодателем
   │  Экран показывает: условия договора, результаты всех проверок,
   │  предупреждения по штатному расписанию
   │
👤 9. Подписание работником
   │
🤖 10. После подписания
   │  • постановка на внутренний воинский учёт
   │  • начисление отпускного стажа с даты приёма
   │  • напоминание об окончании испытания за 5 дней
   │  • формирование обязательств перед госорганами (см. документ 04)
   │
⏳ 11. Отправка сведений в госорганы
      ЕФС-1 в СФР · уведомление МВД (иностранец) · сведения в военкомат
      Первая отправка каждого вида у клиента — только с подтверждением 👤
```

### Что нужно проверить юристу

1. **Перечень документов при приёме** (ст. 65 ТК РФ). Программа запрашивает:
   паспорт, СНИЛС, ИНН, сведения о трудовой деятельности, банковские реквизиты,
   военный билет. ⚠ ИНН и банковские реквизиты не названы в ст. 65 как
   обязательные — правомерность их истребования требует оценки.
2. **Момент возникновения трудовых отношений.** Программа считает днём приёма
   дату начала работы из заявки. Фактический допуск к работе до оформления
   договора (ч. 2 ст. 67 ТК РФ) программа не отслеживает. ⚠
3. **Срок оформления договора** — программа ставит срок 3 календарных дня
   от даты начала работы. Требует проверки соотношение с ч. 2 ст. 67 ТК РФ.
4. **Ознакомление с локальными актами до подписания договора** (ч. 3 ст. 68 ТК РФ).
   Программа формирует лист ознакомления в составе пакета, то есть одновременно
   с договором, а не строго до него. ⚠

## 2. Испытательный срок

### Схема

```
👤 При приёме указывается продолжительность испытания в месяцах
   │
🤖 Проверка допустимости
   │  • работник моложе 18 лет → условие об испытании удаляется автоматически,
   │    в процессе фиксируется причина (ст. 70 ТК РФ)
   │  • свыше 3 месяцев → ⛔ приём остановлен как превышение предела ⚠
   │    (см. документ 06, расхождение № 2: для руководителей закон допускает
   │     6 месяцев, программа этого не учитывает)
   │
🤖 Расчёт даты окончания испытания
   │  дата начала работы + (число месяцев × 30 дней) ⚠
   │  (см. документ 06, вопрос № 3: месяц считается как 30 дней,
   │   а не как календарный месяц)
   │
🤖 За 5 дней до окончания — задача руководителю
   │
👤 Решение о результате испытания
   │  • результат положительный → никаких действий, испытание истекает
   │  • результат отрицательный → переход к процессу увольнения по ст. 71 ТК РФ
```

### Что программа НЕ отслеживает

- Периоды фактического отсутствия работника, не засчитываемые в срок испытания
  (ч. 7 ст. 70 ТК РФ): болезнь, отпуск. Срок испытания на эти периоды
  не продлевается. ⚠
- Иные категории, которым испытание не устанавливается (ч. 4 ст. 70 ТК РФ):
  беременные, женщины с детьми до полутора лет, избранные по конкурсу,
  окончившие обучение и поступающие впервые по специальности в течение года,
  приглашённые в порядке перевода, договор до 2 месяцев. Программа
  проверяет только несовершеннолетие. ⚠ **Существенный пробел.**

## 3. Отпуск

### Годовой цикл

```
🤖 Ежемесячно: начисление 2,33 дня отпускного стажа за отработанный месяц
   │
🤖 Построение проекта графика на следующий год
   │  • распределение по работникам
   │  • контроль: распределены ли все 28 дней
   │  • контроль: есть ли часть не менее 14 дней подряд (ст. 125 ТК РФ)
   │  • контроль: не уходит ли в отпуск одновременно более половины
   │    работников подразделения
   │  ⚠ Программа НЕ учитывает льготные категории, имеющие право
   │    на отпуск в удобное время (см. документ 06, вопрос № 8)
   │
👤 Утверждение графика — не позднее 17 декабря
   │  ⚠ Дата получена как «31 декабря минус 14 дней». Требует подтверждения
   │
──── далее по каждой записи графика ────
   │
🤖 За 30 дней: напоминание работнику и руководителю
   │
⏳ За 14 дней: уведомление работника о начале отпуска (ч. 3 ст. 123 ТК РФ)
   │  Обязательное по закону; программа формирует и направляет сама,
   │  человек может отменить в течение 24 часов
   │
👤 За 7 дней: приказ о предоставлении отпуска (Т-6)
   │
🤖 За 5 дней: задача бухгалтерии выплатить отпускные
   │  Крайняя дата выплаты — за 3 дня до начала отпуска (ч. 9 ст. 136 ТК РФ)
   │  ⚠ Вид дней (календарные или рабочие) требует определения —
   │    см. документ 06, вопрос № 7
   │  Программа НЕ выплачивает деньги, только напоминает
   │
🤖 Ежеквартально: отчёт по накопленным остаткам
      Работник без отпуска два года подряд → красный флаг (ч. 4 ст. 124 ТК РФ)
```

### Что нужно проверить

1. Правило начисления 2,33 дня за месяц и округление излишка от 15 дней
   до полного месяца.
2. Дату утверждения графика.
3. Порядок определения крайней даты выплаты отпускных.
4. Перечень категорий с правом на отпуск в удобное время.

## 4. Увольнение по собственному желанию (п. 3 ч. 1 ст. 77 ТК РФ)

### Схема

```
👤 Заявление работника либо команда руководителя
   │
🤖 Определение даты увольнения
   │  • общий случай: дата подачи заявления + 14 календарных дней
   │  • работник на испытании: + 3 дня (ч. 4 ст. 71 ТК РФ)
   │  • обстоятельство из перечня → без отработки (ч. 3 ст. 80 ТК РФ):
   │      выход на пенсию · зачисление в образовательную организацию ·
   │      установленное нарушение работодателем · переезд к месту работы супруга
   │      ⚠ Перечень программы уже, чем «другие случаи» в ч. 3 ст. 80
   │  • запрошена дата раньше расчётной → программа не отказывает,
   │    а помечает: досрочное увольнение возможно только по соглашению сторон
   │
🤖 Блокирующие проверки
   │  • нетрудоспособность и отпуск НЕ блокируют — программа исходит из того,
   │    что запрет ч. 6 ст. 81 ТК РФ относится к инициативе работодателя ⚠
   │  • беременность, отпуск по уходу за ребёнком — тоже не блокируют
   │  • работник моложе 18 лет — предупреждение без блокировки
   │  • материально ответственное лицо → предупреждение о необходимости
   │    инвентаризации, процесс продолжается
   │  • признак трудового спора → ⛔ процесс остановлен
   │
🤖 Расчёт сумм (см. раздел «Расчёт» ниже)
   │
🤖 Формирование пакета
   │  заявление работника · приказ (Т-8) · записка-расчёт (Т-61) ·
   │  сведения о трудовой деятельности (СТД-Р) · обходной лист
   │
👤 Подтверждение увольнения и подписание приказа
   │
👤 Ознакомление работника с приказом
   │
👤 Выплата расчёта в день увольнения (ст. 140 ТК РФ)
   │  Программа ставит задачу и контролирует срок, но НЕ производит выплату
   │
🤖 После увольнения
   │  • отзыв доступов в информационных системах
   │  • перевод личного дела в архив, срок хранения 50 лет
   │  • сохранение возможности выдать справки в течение 3 лет
   │
⏳ Отправка сведений: ЕФС-1 в СФР, уведомление МВД, сведения в военкомат
```

### Что программа НЕ делает

- Не отслеживает право работника отозвать заявление до истечения срока
  предупреждения (ч. 4 ст. 80 ТК РФ). ⚠ **Существенный пробел.**
- Не отслеживает продолжение работы после истечения срока предупреждения,
  при котором увольнение не производится (ч. 6 ст. 80 ТК РФ). ⚠
- Не выдаёт бумажную трудовую книжку и не направляет уведомление о необходимости
  её получить, если работник от электронного порядка отказался.

## 5. Увольнение по соглашению сторон (п. 1 ч. 1 ст. 77 ТК РФ)

### Схема

```
👤 Инициатива любой из сторон
   │
🤖 Дата увольнения = дата, согласованная сторонами
   │  Срок предупреждения не применяется
   │
🤖 Блокирующие проверки — тот же состав, что и при увольнении
   │  по собственному желанию
   │
🤖 Расчёт сумм; выходное пособие — только если указано явно ⚠
   │  Программа не определяет размер пособия сама
   │
🤖 Формирование пакета
   │  соглашение о расторжении · приказ (Т-8) · записка-расчёт (Т-61) ·
   │  СТД-Р · обходной лист
   │
👤 Подписание соглашения обеими сторонами
👤 Подтверждение увольнения и подписание приказа
👤 Выплата расчёта в день увольнения
   │
🤖 / ⏳ Постобработка и отчётность — как при увольнении по собственному желанию
```

### Что нужно проверить

1. Текст соглашения о расторжении (документ 03a) — достаточность условий.
2. Отсутствие в программе контроля того, что соглашение подписано **до**
   издания приказа. Порядок шагов задаётся человеком. ⚠
3. Аннулирование соглашения возможно только по взаимному согласию сторон;
   программа этого не отслеживает. ⚠

## Расчёт сумм при увольнении

Применяется одинаково ко всем основаниям.

| Составляющая | Как считает программа | Требует проверки |
|---|---|---|
| Заработная плата за отработанное время | оклад ÷ число рабочих дней месяца × отработанные рабочие дни | ⚠ |
| Средний дневной заработок | среднемесячный заработок ÷ 29,3 | ⚠ соотношение со ст. 139 ТК РФ и постановлением Правительства РФ № 922 |
| Компенсация за неиспользованный отпуск | средний дневной заработок × число неиспользованных дней | ⚠ |
| Удержание за отпуск, использованный авансом | средний дневной заработок × число дней сверх заработанных | ⚠ основания и пределы удержания (ст. 137 ТК РФ) |
| Выходное пособие | среднемесячный заработок × указанное число месяцев; по умолчанию 0 | ⚠ |
| НДФЛ | 13 % от начисленного | ⚠ **прогрессивная шкала не реализована**, см. документ 06, вопрос № 4 |
| Предел удержаний | не более 20 % от суммы после удержания НДФЛ | ⚠ ст. 138 ТК РФ |

**Важно:** расчёт всегда требует подтверждения человека. Программа не производит
выплату ни при каких настройках — такой функции в ней нет.

---

## Основания увольнения, не реализованные в программе

Программа поддерживает четыре основания: по собственному желанию, соглашение
сторон, истечение срока договора, неудовлетворительный результат испытания.

Любое иное основание — включая сокращение численности или штата, увольнение
за виновные действия, несоответствие занимаемой должности, ликвидацию —
программа выполнять отказывается и предлагает оформить процедуру вне системы.
Это не настройка, а свойство устройства программы.
