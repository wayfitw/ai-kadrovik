## 1. Разрыв «реестр объявляет — код не исполняет»

Главный технический риск. Найдено при разборе пакета:

| Правило | Что объявлено в параметрах | Что по описанию реально делает | Действие в MVP |
|---|---|---|---|
| `probation_period_limits v1` | Исключения: minors, pregnant, has_child_under_1_5, fixed_term_under_2_months, graduate_first_job, invited_by_transfer | Проверяется только несовершеннолетие (06, D3) | Реализовать проверку **всех** объявленных категорий через поля карточки; поля, которых нет в данных, — отметить `data_missing`, не молча пропускать |
| `archive_personal_file v1` | 50 лет / 75 лет для документов до 2003 г. | Единый срок 50 лет (06, D11) | Реализовать дифференциацию по дате как объявлено |
| `vacation_recall v1` | Согласие работника — обязательное условие | Спрашивают только руководителя (06, D6) | Добавить состояние «ожидает согласия работника»; в MVP отмечает кадровик |

Линтер `scripts/lint_registry.py` должен ловить такие случаи автоматически:
параметр правила без ссылки из кода → ошибка сборки.

## 3. Что юрист почти наверняка пометит «ИСПРАВИТЬ»

Прогноз по открытым источникам, не правовое заключение. Нужны **тесты и точки расширения**,
чтобы правка заняла часы, а не дни:

| Код | Сейчас в реестре | Вероятная правка | Подготовка в MVP |
|---|---|---|---|
| B1 | Испытание: месяц = 30 дней | Календарные месяцы (ст. 14 ТК) | `add_months` уже в `app/calendar`; расчёт через параметр `month_mode` |
| B2 | НДФЛ 13 % плоско | Прогрессивная шкала или вынос в бухгалтерию | Ставка — параметр правила; расчёт изолирован в одной функции |
| C4 | Дата увольнения = заявление + 14 | Течение со следующего дня | Флаг `count_from_next_day` в `app/calendar`, по умолчанию как в реестре |
| A3 | МВД: от приказа | От даты заключения/прекращения договора | Обе даты хранятся; триггер — параметр |
| D1 | Отзыва заявления нет | Обязателен | Поле `withdrawn_at`, состояние `withdrawn` без логики |
| D3 | Испытание: только возраст | Все категории ст. 70 | См. раздел 1 |
| C6 | Переносы 2027 | Уточнить после постановления | Календарь — данные с пометкой «предварительный» |

## 4. Контрольные примеры для `tests/golden/`

Числа — **как даст реестр**, не «как правильно». После вердикта юриста ожидаемые значения
обновляются вместе с версией правила.

1. Приём 1 марта 2027, испытание 3 месяца → дата окончания по текущему правилу (30-дневные
   месяцы) и по календарным месяцам — оба значения в тесте, активен первый.
2. Заявление об увольнении подано 3 ноября 2026 (вторник) → дата увольнения по реестру;
   проверить попадание на выходной/праздник (4 ноября).
3. Увольнение 15 декабря 2026, принят 1 февраля 2026, отпуск не использован → стаж,
   дни компенсации, округление по реестру.
4. Увольнение с отпуском авансом: отгулял 28 дней, отработал 7 месяцев → удержание
   и предел 20 % по реестру.
5. Выходное пособие: средний заработок за 12 месяцев, 29,3 → сумма по реестру.
6. ЕФС-1 при приёме в пятницу 23 октября 2026 → срок = следующий рабочий день (26 октября).
7. Уведомление МВД при приёме иностранца 30 октября 2026 (пятница) → 3 рабочих дня
   через выходные и 4 ноября.
8. График отпусков: отдел 10 человек, у двоих остатки > 2 лет → они первыми,
   нигде не больше 5 одновременно, у каждого часть ≥ 14.

## 5. Уровни автономии — что проверить в коде

- A3 (из `legal-package/05`): `forbidden_apply_employer_ukep`, переводы денег,
  дисциплинарные взыскания, увольнение по инициативе работодателя, сокращение,
  отказ кандидату, изменение аудита и правил — **ни одного эндпоинта, ни одной функции**.
  Тест: grep по кодовой базе на имена A3-правил возвращает только реестр и этот документ.
- A1 → A2 автоматически: первые 30 дней организации; первая отправка каждого типа отчёта.
- Окно отмены A1 никогда не ведёт к пропуску срока: если до срока меньше окна — окно
  сокращается; если и это невозможно — немедленная отправка + уведомление постфактум.
